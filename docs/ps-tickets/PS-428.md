# PS-428 — Worker-owned Rate Browse and Print merge execution

## Placement record

### Business rule/workflow being changed

Rate Browse fan-out and Print Queue PDF merge must execute exactly once per live durable generation, survive API/worker restarts, and prevent a timed-out attempt from overlapping or publishing over a successor.

### Canonical backend/domain/read-model/policy owner

- `rate_browse_jobs` plus `rate-browse-worker.ts` own Rate Browse input, claim generation, heartbeat, cancellation acknowledgement, provider fan-out, and terminal result.
- `print_queue_merge_jobs`, `print_queue_pdf_chunks`, and the dedicated Print Queue worker own merge input, generation claims, resumable chunks, artifact publication, and terminal result.
- Sync lane advisory locks plus the timeout-derived reaper lease own sync cancellation/retry exclusion.

### Current duplicated/unsafe owners

- The API-local Rate Browse `queueMicrotask` scheduler could lose work on restart and start duplicate fan-out across instances.
- `startPrintJob` invoked merge work in the API process, while process memory owned the active entries and completed PDF bytes.
- Fixed stale/reaper thresholds could expire an attempt before its configured deadline.

### Where bad/stale/incomplete data can enter

- API process exit after durable job creation but before local detached execution.
- Worker exit after a PDF chunk is stored but before its snapshot is updated.
- A late provider/fetch result from an expired generation.
- A timeout that aborts cooperatively but releases the queue/lane before the original promise settles.

### Callers that must delegate to the owner

- `/rates/browse/workflow` persists serializable intent and enqueues the Rate Browse worker.
- Print Queue start persists selected entries/options and enqueues the Print Queue merge worker.
- Status and serving paths read durable snapshots/chunks; they do not infer or recreate work.

### Wrapper/resolver/helper logic to delete or explicitly forbid

- API-local detached schedulers and direct `runMergeJob` calls are forbidden.
- A route/UI must not claim generations, run provider fan-out, assemble PDFs, or publish terminal artifacts.
- Stale generations must not write snapshots or overwrite newer PDF chunks.

### Frontend role: display/action only; no authoritative business logic

The frontend starts a requested operation and renders backend status/artifact DTOs. It does not own retries, timeouts, official completion, merge chunks, or rate/provider results.

### Backend boundary tests required

- One active Rate Browse reservation per request key.
- Fresh claims cannot overlap; old generations cannot update snapshots or artifacts.
- Deadline cancellation is acknowledged only after the original work promise settles.
- Stored Print merge chunks survive restart and are resumable.
- A 20-minute live job is not reaped when the configured handler deadline is 25 minutes.

### Workflow/UI proof required when operator-facing

Focused guards prove the API only enqueues, workers own execution, durable status remains readable across process boundaries, and completed chunks are served from the artifact store.
