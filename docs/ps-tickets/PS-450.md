# PS-450 — Inventory deductions via fulfillment outbox + pg-boss consolidation

## Outcome

PS-450's durable runtime was already present on stable through commit
`101d7dad721b9d7e780285e0f2fb43f8e0e82688`. This closeout adds the missing
read-only operator projection for unsettled inventory-deduction work without
changing the locked deduction engine or any shipped/cancelled write path.

Run the report with:

```bash
npm run inventory:deduction-report -- --limit 100
```

The JSON output contains only operational IDs and retry state. It excludes
customer detail and reports unresolved rows as `pending`, `processing`,
`retrying`, `exhausted`, or `parked_kill_switch`. When the validated
`INVENTORY_AUTO_DEDUCT` switch is off, every unresolved row is visibly parked.

## Canonical ownership

- `order-lifecycle-command.ts` creates immutable fulfillment facts and exact
  line claims in the same transaction as the shipped transition.
- `inventory-deduction-outbox.ts` owns durable inventory intent, dedupe keys,
  missing-intent recovery, and delegation to the deduction owner.
- `fulfillment-deductions.ts` remains the unchanged canonical stock-movement,
  ledger-idempotency, and kill-switch owner.
- `fulfillment/outbox.ts` owns claims, crash-lease recovery, retries, and
  settlement. Inventory events return before marketplace/order projections.
- `sync-job-queue.ts` owns pg-boss schedules and singleton admission.
- `inventory-deduction-report.ts` is a SELECT-only projection; it owns no
  mutation or retry policy.

## Safety

- No locked runtime file was modified for this closeout.
- No SQL migration was added.
- No live order, shipment, label, postage, provider, marketplace, inventory,
  ledger, or production application row was read or mutated during tests.
- The report performs one bounded SELECT and does not expose customer PII.
- Existing indexes support its bounded status/next-run ordering; no speculative
  index or production schema change was introduced.
- The PS-413 wiring guard now follows the post-PS-444 `durableCreated` receipt
  variable instead of its obsolete pre-receipt local name; runtime label logic
  is unchanged.

## Verification

The ticket-level guard proves placement, kill-switch ordering, retry/lease
recovery, inventory-only settlement isolation, pg-boss scheduling, and report
read-only behavior. The offline integration injects a transaction spy to prove
the disabled kill switch starts zero database transactions, then uses PGlite to
prove all report states and that the query leaves the outbox byte-for-byte
unchanged.

Release gates also run the existing PS-247, PS-413, PS-414, PS-424, inventory
source-of-truth, inventory auto-deduct, pg-boss/outbox, sync-admission,
typecheck, build, and mandatory source-of-truth guard suites.
