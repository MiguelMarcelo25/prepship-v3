# PS-448 - View GET loads on TanStack Query

## Placement

- Backend Dashboard, Billing, Analysis, and Settings endpoints/read models remain the
  source of truth for every returned DTO and business value.
- `web/src/lib/query-client.ts` owns the frontend freshness policy: five-minute stale
  time, thirty-minute cache retention, no focus refetch, and background refetch on stale
  remounts for the four PS-448 view-key roots. Fresh remounts remain request-free. The
  conservative global no-remount default remains unchanged for other query families.
- Each view owns only endpoint-shaped query keys, loading/error presentation, and
  explicit invalidation after operator mutations. No business calculation moved into
  React.
- Imperfect data/request pressure entered at view remounts: imperative effects discarded
  the previous component state and repeated otherwise-identical GETs on every navigation.

## Implementation history

The four runtime slices were already present on the stable branch before this Trello

in-app sidebar, and asserts that the Dashboard GET ledger is byte-for-byte unchanged.

All browser traffic is mocked. The optional production pressure audit accepts a
task-scoped database URL and runs aggregate `SELECT` statements against
`pg_stat_statements` only. Neither proof calls a live provider, buys or prints a label,
charges postage, notifies a marketplace, or mutates production orders, shipments,
billing, or inventory.

Two production read-only snapshots were captured on 2026-07-21 at 06:48:51Z and
06:53:00Z. The four historically busiest order-list statement IDs retained exactly
`1,061,193`, `902,647`, `801,076`, and `721,722` calls across that 249-second window
(zero additional calls for each fingerprint). This is aggregate pressure evidence only;
the browser ledger above remains the deterministic proof that a fresh Dashboard revisit
does not repeat its GET requests.
