# PS-449 - Billing finalize endpoint and credit-note path

## Canonical owner

- `src/services/billing-finalization-policy.ts` owns close admission, the
  transaction boundary, client advisory locking, frozen invoice totals,
  immutable finalization summaries, credit idempotency, and remaining-balance
  enforcement.
- `src/services/billing-invoice-totals.ts` remains the shared backend totals
  owner used by invoice reads and finalization. Routes and React do not
  recompute money.
- `drizzle/0065_billing_close_workflow.sql` is the database backstop. It
  serializes overlapping client-period writes, blocks mutations inside closed
  periods, keeps finalizations and credits append-only, and prevents
  over-crediting.
- `src/routes/billing.ts` is thin transport: permission, tenant scope,
  authenticated actor, policy delegation, response, and audit event.
- `BillingView.tsx` and `BillingCloseWorkflowPanel.tsx` display backend totals
  and send operator intent only.

The earliest imperfect-data boundary is billing regeneration, a sidecar edit,
or a late line insert after an invoice is sent. Generation rejects a finalized
period before rebuilding; the migration trigger uses the same per-client
transaction advisory lock as finalization so concurrent finalize/generate
transactions cannot interleave around the close fact.
