# PS-465 — Hazardous-material declarations and certified label paths

Status: implementation complete; provider/account canary proof and browser review remain release blockers.

## Placement

- Business rule: an operator-entered hazmat declaration must be validated, revisioned, bound to the selected rate, and frozen with the purchased shipment. Active hazmat must never be omitted from a provider request.
- Canonical owner: `src/services/shipping-workflow/hazmat-declaration.ts` owns normalization, validation, semantic identity, and immutable purchase seals.
- Capability owner: `src/services/shipping-workflow/hazmat-capability.ts` and `hazmat-shipping-policy.ts` own client rollout, carrier compatibility, and rate/purchase authorization.
- Persistence owner: `src/services/order-hazmat.ts` owns scoped optimistic writes, label-operation locking, rate invalidation, audit, and frozen snapshot reads.
- Earliest imperfect data: operator input and read-only imported ShipStation advanced-option evidence. Imported evidence is never purchase authority.
- Callers: rates, quote authorization, label purchase, durable ShipStation recovery, and Print Queue preflight delegate to the same sealed facts.
- Frontend role: collect explicit operator facts, render backend capability DTOs and immutable snapshots, and send validate/save intent. It never chooses an official carrier profile or buys postage.
- Forbidden duplicate owner: React/provider wrappers may not infer carrier support, fabricate a hazmat seal, or silently map unsupported fields.

## Carrier matrix

| Path | Rating | Purchase | Provider mapping |
|---|---:|---:|---|
| Connected Stamps.com (`stamps_com`) | Flag + client canary gated | Flag + client canary gated | `shipment.advanced_options.dangerous_goods=true` |
| USPS from ShipStation (`usps`) | Blocked | Blocked | Its carrier guide says dangerous goods are unsupported |
| ShipStation UPS dry ice | Flag + client canary gated | Flag + client canary gated | `dry_ice` plus exact `dry_ice_weight` |
| ShipStation UPS generic dangerous goods | Blocked | Blocked | No certified account/provider mapping |
| Direct UPS | Blocked | Blocked | No certified native `ChemicalRecord` mapper |
| Walmart Shipping | Blocked | Blocked | Existing false/omitted hazmat shapes are never accepted |

The mapper deliberately does not send `limited_quantity`, `regulated_content_type`, product-level dangerous-goods objects, or emergency contacts on the two enabled profiles without carrier-specific proof. Official references: [ShipStation dangerous goods](https://docs.shipstation.com/apis/shipengine/docs/shipping/dangerous-goods), [Stamps.com USPS](https://docs.shipstation.com/apis/docs/carriers/stamps-usps-guide), [USPS from ShipStation](https://docs.shipstation.com/apis/shipengine/docs/carriers/usps-from-shipengine), and [UPS](https://docs.shipstation.com/apis/shipengine/docs/carriers/ups).

## Persistence and safety

- Migration `0078_order_hazmat_declarations.sql` adds declaration/material sidecars and an immutable shipment snapshot sidecar. It performs no backfill and no update/delete against `orders` or `shipments`.
- Shipment snapshots have database constraints for active status, profile, schema version, revision, hash, and capture kind. UPDATE, DELETE, and TRUNCATE are blocked by triggers.
- Snapshot JSON is re-sealed and checked against the indexed revision/profile/hash before it is shown as frozen truth.
- Saving an awaiting-shipment declaration uses an optimistic revision, obtains the label-purchase lock, rejects unresolved provider operations, clears the prior Best Rate, and records a required audit event.
- Rate cache identity, quote context, selected rate, operation request, durable receipt, shipment snapshot, and Print Queue preflight share the declaration revision/hash/profile.
- No-declaration label bodies, rate-estimate endpoint selection, fingerprints, and Print Queue response fields remain unchanged.

Recommended order: deploy migration with all flags off; enable read/write for one trained client; validate migration/UI/audit; enable one documented rate profile; run provider account-options and staging rate proof; enable purchase only after an approved canary; retain the global purchase kill switch.
