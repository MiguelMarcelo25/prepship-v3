# PS-447 — Durable ShipStation admission and cancellation

## Source of truth

- `src/lib/shipstation/client.ts` is the only ShipStation v2 admission point. It owns per-key
  priority (`interactive > batch > background`), request-wide cancellation, retries, and
  provider `Retry-After` handling.
- `src/lib/shipstation/durable-rate-limiter.ts` owns the Postgres-backed shared token state.
  The existing `rate_limiter_state.updated_at` timestamp also carries a fleet-wide pause; no
  schema or historical shipping-data change is required.
- `src/services/rates.ts` owns only the local quote-fanout concurrency queue and uses the same
  three priority tiers. It does not rank or mint rate truth outside the existing backend owner.

## Root cause and routing

The previous API/worker clients could have independent in-memory budgets, a 429 paused only the
request that received it, and a caller timeout began after limiter admission. Batch work also
shared the lowest background lane. PS-447 routes every v2 request through one per-key gate,
persists provider backpressure in the shared bucket, and uses one signal across admission,
network fetch, Retry-After, and retry backoff. Recalculation/backfill is `batch`; sync, tracking,
and recovery reads are `background`; operator quotes and label operations remain `interactive`.

## Rollout

Set `RATE_LIMITER_BACKEND=durable` on every process that can call ShipStation (API, sync worker,
and print worker). Defaults remain conservative:

- `SHIPSTATION_RATE_LIMIT_BATCH_BURST_RESERVE=4`
- `SHIPSTATION_RATE_LIMIT_BATCH_PER_MINUTE_RESERVE=20`

No GitHub Actions are required. Roll out one exact commit to every service and confirm the
reported limiter backend is `durable` before closing the ticket.

## Safety and proof

The certification is offline. It does not purchase or void labels, notify a marketplace, or
mutate production orders/shipments. `npm run test:ps-447-shipstation-admission` proves two limiter
instances share one budget, a shared pause reaches the second instance, cancellation stops
permit polling, priorities are strictly ordered, and label creation is not assigned a lower lane.
