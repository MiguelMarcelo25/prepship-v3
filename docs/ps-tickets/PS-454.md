# PS-454 - Orders read-model and command-service extraction

## Placement

- **Workflow:** Orders list/detail DTO composition and order override/Best Rate
  persistence must be backend-owned services; the route may validate, enforce
  scope/editability, delegate, and serialize the service result.
- **Canonical read owner:** `src/services/orders-read-model.ts` owns canonical
  list/detail order projection, legacy client identity, recipient evidence,
  package facts, and read-only bulk snapshot composition.
- **Canonical command owner:** `src/services/orders-overrides-command.ts` owns
  box/dimension coherence, override upsert, Apply Best Rate finalization, and
  saved Best Rate persistence while delegating rate proof, eligibility, package
  facts, and transaction-time editability to their existing authorities.
- **Imperfect-data entry point:** before the extraction, transport handlers in
  `src/routes/orders.ts` assembled DTO truth and persisted overrides/rates
  inline, allowing route-local policy to drift from the backend owners.
- **Callers:** `src/routes/orders.ts` retains auth, scope, validation,
  `LOCKED_STATUSES`, and `assertOrderEditable`, then delegates to the two
  canonical services.
