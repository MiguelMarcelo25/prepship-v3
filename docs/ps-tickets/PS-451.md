# PS-451 — Close the order-edit TOCTOU boundary

## Outcome

The production write guard introduced by `1e02217b` already serializes protected
order edits with lifecycle transitions. PS-451 adds deterministic behavioral proof
that a PATCH whose route preflight observed `awaiting_shipment` cannot write after a
concurrent shipment commits `shipped`.

## Architecture placement

- **Business rule:** a non-admin order edit may write only while the order's canonical
  effective lifecycle is non-terminal at the final database write boundary.
- **Imperfect-data entry point:** `assertOrderEditable` is an early route preflight; its
  result can become stale before persistence when a label purchase or status sync ships
  the same order concurrently.
- **Canonical owner:** `src/services/order-editable-write.ts`, which locks the order row,
  re-reads canonical lifecycle truth, rejects terminal state, and only then invokes the
  protected write callback inside the same transaction.
- **Callers:** PATCH `/:id`, `/residential`, `/selected-pid`, `/selected-package-id`,
  `/best-rate`, and `/save-dims` delegate through the order override command owner;
  `/shipped-external` delegates through the row-locked lifecycle command owner.
- **Duplicate logic:** none added. `assertOrderEditable` remains the unchanged fast-path,
  scope, audit, and HTTP-error owner; `LOCKED_STATUSES` remains unchanged.
- **Boundary proof:** `scripts/ps-451-order-editable-write-integration.ts` repeats a
  deterministic stale-preflight/concurrent-ship race 25 times and proves zero override
  writes on every shipped row. It also proves the ordinary awaiting write still succeeds.

## Lockdown override

Per user override `unlock shipped data` on 2026-07-21, the only locked runtime file
touched is `src/services/order-editable-write.ts`. The change extracts its existing
transaction body into an exported in-transaction boundary so the real production rule
can be exercised by an in-memory test; the production wrapper still opens the transaction
and delegates to that same boundary. No route, `assertOrderEditable`, `LOCKED_STATUSES`,
schema, shipped/cancelled record, or admin override policy was changed.

## Safety

The behavioral test uses only an in-memory PGlite fixture. It cannot reach production,
providers, labels, postage, marketplace notifications, billing, inventory, or real
shipped/cancelled rows.
