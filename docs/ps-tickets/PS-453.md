# PS-453 - Per-job durable Print Queue merge snapshots

## Placement

- **Workflow:** PDF merge status and immutable artifact publication must survive
  API/worker restarts without allowing two generations to publish the same job.
- **Canonical owners:** `print_queue_merge_jobs` and
  `src/services/print-queue/merge-job-store.ts` own per-job status, while
  `print_queue_pdf_chunks` and `src/services/print-queue-pdf-store.ts` own
  generation-fenced PDF bytes. The dedicated Print Queue worker owns execution
  and recovery.
- **Imperfect-data entry point:** the former latest-run singleton and detached
  persistence could overwrite concurrent status or report `done` before bytes
  were durable.
- **Callers:** Print Queue routes read the requested backend snapshot and render
  derived status. They do not infer worker liveness or publish PDF artifacts.

## Completion

Migration `0064` replaced the singleton with one row per `job_id`. PS-428 then
made merge execution worker-owned, added generation claims/heartbeats in `0067`,
and made chunk persistence mandatory before terminal `done`.

PS-453 closes the remaining visibility gap without weakening those fences:
after four missed 15-second heartbeats, the status owner presents the active
snapshot as `interrupted/stale` while keeping its generation active. Only after
the timeout-derived execution lease expires does it derive a terminal error.
The worker can therefore recover the same job promptly without a false second
executor or a permanent phantom `running` state.

The `DURABLE_PRINT_QUEUE_PDF` production canary completed on 2026-07-14 as
recorded in `PRINT_QUEUE_MERGE_DURABILITY_AUDIT.md`. PS-428 subsequently made
durable chunks mandatory; the legacy environment key now defaults on and cannot
disable the canonical artifact store.

## Safety

Per user override `unlock shipped data` on 2026-07-21, the status/worker files
were updated only to share heartbeat thresholds and derive read-only status.
No order, shipment, Print Queue entry, label, postage, marketplace confirmation,
or inventory data is changed. Verification uses synthetic migrated-database
fixtures and existing canary evidence; it creates no live print job.
