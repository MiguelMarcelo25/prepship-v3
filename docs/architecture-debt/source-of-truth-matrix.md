# Source-of-Truth Matrix

PrepShip does not need one source of truth for every fact. It needs explicit
ownership per layer: external source, local operation, frozen side-effect
snapshot, derived/read model, and cache.

| Domain | External source truth | Local operational truth | Derived/read-model truth | Ephemeral cache | Frozen snapshot truth | Mutation owner | Read owner | Current weak points / dual truths | Recommended direction |
|---|---|---|---|---|---|---|---|---|---|
| Orders | ShipStation/Walmart/eBay/Amazon/Shopify order APIs | `orders` (`sourceProvider`, `sourceAccountId`, `sourceOrderId`, `orderStatus`, `rawSourcePayload`) | Orders list DTO in `src/routes/orders.ts`; dashboards | Sidebar/init counts | Terminal local status decisions and raw import payload | Store connectors, `src/services/order-sync.ts`, direct marketplace import functions | `src/routes/orders.ts`, dashboard/analysis/billing reads | Direct marketplace functions mirror into `orders`; `store_orders` and `orders` can drift; terminal status is protected | Store connector orchestrator owns import; order route only exposes normalized DTOs and guarded awaiting mutations. |
| Order items | Marketplace order line payloads | `order_items` (`sku`, `quantity`, `lineTotal`, `clientId`, `storeId`, `orderStatus`) plus raw `orders.items` compatibility | SKU analytics, dashboard top SKUs, billing details | Analytics cache | Billing generated item counts after invoice line creation | `src/services/order-items.ts`, import/sync maintenance | Dashboard/analysis/billing routes | Some services still fall back to `orders.items` JSONB | Make `order_items` canonical for analytics/billing; keep `orders.items` raw compatibility only. |
| Store/source connectors | Store APIs and marketplace account state | `store_orders` migration, `orders.source*`, credential/store account tables | Sync status and reconciliation reports | Sync job queue/dedupe | Imported raw payload at sync time | `src/services/store-connector-orchestrator.ts`; provider connectors | Sync, reconciliation, admin routes | Some Vercel provider functions still do direct mirror work | Provider functions call store orchestrator and shared normalizer only. |
| Carrier connectors | Carrier/ShipEngine/ShipStation APIs | Carrier connector contracts in `src/connectors/carrier/*` | Carrier diagnostics and account lists | In-process carrier account cache in rates/labels | Provider response normalized at label/rate side effect | `src/services/carrier-connector-orchestrator.ts` and provider connectors | Rates, labels, direct-carrier functions | Direct carrier serverless paths duplicate some connector/persistence work | Keep connectors thin: quote/create/void/track only; workflow service owns orchestration. |
| Carrier accounts / direct assignments | Credential/account provider portals | `carrier_accounts` (`provider`, `clientId`, `source`, `active`) and `carrier_account_clients` | Settings UI account display; carrier lists | Frontend carrier cache | Shipment provider/account snapshot (`shipments.providerAccountId`, `providerAccountNickname`) | Credential account services/routes; scope guard | Rates/labels/settings | Legacy `clientId` and assignment rows coexist; frontend hides/labels accounts too | Backend eligibility service returns scoped accounts; frontend displays only. |
| Rates / Best Rate | Live carrier quote at quote time | `src/services/rates.ts` normalized rates, `order_overrides.bestRateJson` as current recommendation | Orders table best-rate display; Rate Browser rows | `rate_cache` (`rates`, `bestRate`, `diagnostics`, `fetchedAt`) | `shipments.selectedRateJson` after label purchase | Rate service and strict recalculation workflow | Orders UI, Rate Browser, billing reads | Frontend can still seed/pick/display rates; cache must not be billing truth | Backend owns live best-rate selection and exact request fingerprint; UI consumes state. |
| Selected rate | Carrier quote selected by operator | `order_overrides.bestRateJson`, `selectedPid`, panel form before label | UI selected row and side-panel state | None except transient UI | `shipments.selectedRateJson`, `selectedPid`, `selectedPackageId`, provider/account fields | Backend label workflow | Orders detail, billing, reprint/recovery | Selected before label is partly frontend state; proof/fingerprint exists but future lifecycle can be clearer | Backend selected-rate primitive becomes workflow state; label purchase only accepts exact proof. |
| Labels / shipments | Carrier label API response | `shipments` (`labelUrl`, `labelTracking`, `labelCost`, provider/account, `voided`, confirmation columns) | Orders shipped display, billing line references | Mock label access cache for test labels | Shipment row is the irreversible local label snapshot | `src/services/labels.ts`, `src/services/direct-label-persistence.ts` | Label routes, print queue, billing, reports | Provider side effect can succeed before all local persistence/queue/outbox steps | Add idempotent label operation/lifecycle record before provider call; shipment remains frozen snapshot. |
| Print Queue | None external; local operator workflow | `print_queue_orders` (`status`, `printCount`, `lastPrintedAt`, `queuedAt`) | Queue drawer grouping/history | Durable job snapshots in `src/services/print-queue.ts` | Print confirmation timestamps and queue row history | Print queue service/routes | Orders UI queue panel | Create+queue combines label purchase and queue insertion with partial-success recovery | Queue operation should attach to label operation id and expose per-order lifecycle state. |
| Fulfillment outbox / marketplace confirmation | Marketplace/source API confirmation result | `fulfillment_outbox` (`eventType`, `provider`, `dedupeKey`, `status`, attempts, last error) and shipment confirmation columns | Recovery/status diagnostics | Scheduler in-memory polling | Confirmation success/failure timestamps/status | `src/services/fulfillment/outbox.ts`; store connector orchestrator | Scheduler, recovery scripts, orders diagnostics | Local shipped can be true while marketplace confirmation pending/failed | Surface confirmation lifecycle as backend workflow DTO; keep outbox as durable side-effect owner. |
| Inventory ledger / balance | PrepShip warehouse operations | `inventory.stockQty`; `inventory_ledger` movement history | Low stock, velocity, dashboard risk | Analytics/reporting cache | Ledger movement rows | `src/services/inventory.ts`, `src/routes/inventory.ts`, fulfillment deductions | Inventory UI, dashboard, analysis | Route/UI still do enrichment and derived calculations; auto-deduct is kill-switch gated | Ledger is audit truth; service owns movement math; UI consumes effective stock DTOs. |
| Package inventory / package defaults | PrepShip package catalog and carrier package definitions | `packages`, `package_ledger`, `client_combo_package_defaults` | Package usage summary, package dropdowns | None durable | Package ledger movements and shipment selected package | Package routes/services; combo default service | Orders UI, Packages UI, billing | Product, combo, and per-order dims/defaults can compete | Backend package-default service returns one default plan; UI applies only awaiting/mutable rows. |
| Product/SKU defaults | Product catalog / operator defaults | `products`, `product_defaults`, `sku_qty_dims`, inventory package id fields | Product pages, Orders panel seed defaults | Product sync cache/process state | Applied order override dims/weight when saved | Product/inventory routes/services | Orders UI, Products/Inventory UI | SKU defaults, combo defaults, and order overrides need clearer precedence | Canonical package/default resolver with explicit precedence and mutable-order guard. |
| Billing line items / invoices | Frozen local operational facts at billing generation | `billing_config`, `client_package_prices`, generated `billing_line_items` | Billing summary/detail/invoice views | Reference rates (`billing_ref_rates`) for estimates | `billing_line_items` with `invoiced` lock | `src/services/billing.ts`, `src/routes/billing.ts` | Billing UI/export | Live shipment/order reads and generated lines coexist; package override repair is sensitive | Generate immutable invoice line snapshots; only explicit repair tasks mutate generated rows. |
| Analytics/reporting | Operational tables at query/generation time | Reporting services over orders/items/shipments/inventory/billing | Dashboard and analysis APIs | `analytics_cache` (`cacheKey`, `payload`, `expiresAt`) | Published/exported reports if saved | `src/services/reporting-metrics.ts`, dashboard/analysis routes | Dashboard/Analysis UI | Raw orders JSON and cache can be mistaken for operational truth | Reporting reads canonical tables; caches are rebuildable and expiry-bound. |
| Frontend UI state | User/operator intent only | React state in `OrdersView`, `RateBrowserModal`, views | Table/modal/panel display | LocalStorage column prefs and in-memory rate entries | None, unless sent to backend and persisted | Frontend components | User/operator | Frontend currently makes provider/rate/queue decisions that affect side effects | Frontend submits intent; backend workflow returns authoritative state and allowed actions. |
