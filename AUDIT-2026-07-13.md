## Executive verdict

The deliberately-built parts of the system are genuinely good: backend-owned rate ranking and proof (PS-313), the fulfillment outbox, purchase locks, pg-boss sync lanes with advisory locks, billing's delete-and-rebuild generation, comprehensive route-level code splitting. **Almost every serious defect lives at a seam** — two features composed unsafely, two writers sharing one surface on different money bases, a retry horizon outliving a lock TTL, or legacy mass predating the current doctrine (the 4,937-line orders route, 2,539 lines of `@ts-nocheck` handlers, in-memory job state under a two-process deployment).

> **Lockdown gate:** roughly a third of Phase 1 touches shipped/cancelled-locked surfaces (`labels.ts`, `shipment-sync.ts` writes, `fulfillment-deductions.ts`, `shipments` schema, the confirmation sweep). Per CLAUDE.md these need DJ to type `unlock shipped data` (the active PS-016–021 override covers only some print-queue/OrdersView work). Items below are tagged **[LOCK]**.

## The four criticals

### C1 — Label purchase POST retries blindly on 5xx: one click can buy up to 5 labels
- **Evidence:** `src/lib/shipstation/client.ts:97,130-142` (5xx → retry, method-agnostic, maxRetries default 5); `src/lib/shipstation/labels.ts:250-257` (`ssCreateLabel` POSTs with no retry override, no idempotency key). Reached via `src/services/print-queue.ts:1243-1247` → `src/services/labels.ts:2217-2240`.
- **Impact:** a 502/504 after ShipStation actually created the label re-buys it up to 4 more times; only the last response is persisted — earlier labels are invisible paid orphans.
- **Fix:** `maxRetries: 1` on the purchase call; treat post-timeout/5xx outcomes as "unknown" and reconcile via `/v2/labels` before any re-send.
- **Effort:** S · **[money path — DJ review]**

### C2 — Crash between provider purchase and DB persist auto-rebuys postage
- **Evidence:** buy at `src/services/labels.ts:2217-2254`, persist transaction after (`:2261-2308`); lock TTL 10min (`src/lib/label-purchase-lock.ts:14`), expired-lock takeover `:62-68`; pg-boss `expireInSeconds: 30*60`, `retryLimit: 1` (`src/services/print-queue-worker.ts:59-66,109-117`); retry re-dispatches orders without results (`print-queue.ts:1603-1612`); PS-288 recovery needs a local shipments row to match — after crash-before-persist there is none.
- **Impact:** worker killed inside the buy→persist window ⇒ postage spent with zero local record; 30min later pg-boss re-delivers, the 10-min lock is gone, order repurchased automatically. Same window for direct carriers.
- **Fix (interim):** raise `LABEL_PURCHASE_LOCK_TTL_SECONDS` above the pg-boss retry horizon (fail closed as `LABEL_PURCHASE_IN_PROGRESS`). **Fix (complete):** durable purchase-intent row written before the provider call, finalized with the persist; unresolved intents force reconciliation, never a re-buy.
- **Effort:** S (interim) / L (complete) · **[LOCK]**

### C3 — Confirmation sweep re-notifies marketplaces for shipments ShipStation itself created
- **Evidence:** `src/services/fulfillment/outbox.ts:477-514` (sweep selects on `label_url IS NOT NULL AND confirmation_status IS NULL`, **no source filter**); `src/services/shipment-label-url-enrich.ts:36-50` (PS-286 backfills label_url onto ShipStation-sourced rows too); dispatch succeeds via `ssMarkOrderShippedV1` with `notifySalesChannel:true` (`src/connectors/store/shipstation.ts:270-297`).
- **Impact:** orders shipped inside ShipStation get a second marketplace ship-notification from PrepShip within 72h — duplicate buyer emails/channel updates.
- **Fix:** `AND s.source IN ('prepship','prepship_v2','test_offline')` in the sweep (or stamp `confirmation_status='not_required'` on SS-sourced inserts).
- **Effort:** S · **[LOCK]**

### C4 — Rate cache key omits ship-from origin: cross-origin cache poisoning up to purchasable proof
- **Evidence:** `src/services/rates.ts:701-726` (cache key — no origin), `src/services/shipping-workflow/rate-fingerprint.ts:175-208` (no origin field); PS-291 made origin operator-selectable (`rate-ship-from-origin.ts:34-79`) and origin changes quotes (`rates.ts:1487`); HTTP dedupe key shares the same gap (`rates.ts:1231,1295`).
- **Impact:** manual rate-shop from a custom origin writes cache rows that order-scoped rating reads as truth; wrong-origin prices can persist as Best Rate and finalize into purchasable proof.
- **Fix:** add `sf=<zip>|<country>` to the fingerprint from resolved ship-from; bump `RATE_CACHE_VERSION`. ~15 lines, two files.
- **Effort:** S
